# واقعه — سورهٔ ۵۶ برای دو نفر

یک وب‌سایت کامل، فقط برای سورهٔ **واقعه (۵۶)**، فارسی و راست‌به‌چپ، با دو پوسته (رُز و شبانه)،
تبدیل سوره/تفسیر، صفحه‌بندی تفسیر، شمارندهٔ تلاوت دو نفر، تاریخچهٔ شمسی و ورود با Supabase Auth.

بدون build، بدون فریم‌ورک، آمادهٔ GitHub Pages.

---

## ۱. پیش‌نمایش سریع

```bash
# هر سرور استاتیک ساده
python3 -m http.server 3000
# سپس http://localhost:3000
```

> باز کردن فایل با `file://` کار نمی‌کند، چون سایت `fetch` می‌زند.

## ۲. ساختار

```
index.html                  ← کل رابط
assets/css/theme.css        ← توکن‌ها، دو پوسته، تایپوگرافی، پس‌زمینه
assets/css/ui.css           ← اجزا، چیدمان، واکنش‌گرا
assets/js/config.js         ← آدرس و کلید publishable سوپابیس + تنظیمات
assets/js/core.js           ← اعداد فارسی، تاریخ شمسی (Intl)، حافظه، توست
assets/js/db.js             ← Auth، شمارنده‌ها، تاریخچه (با fallback محلی)
assets/js/surah.js          ← متن پیوستهٔ سوره، جست‌وجو، پیشرفت، نشان‌ها
assets/js/tafsir.js         ← پارسر و صفحه‌بندی تفسیر
assets/js/app.js            ← کنترلر: تب‌ها، مودال‌ها، مسیر، رویدادها
data/surah56.json           ← متن عربی + ترجمهٔ فارسی، ۹۶ آیه
data/tafsir/*.json          ← فایل‌های تفسیر (۴۹۹، ۵۰۰، ۵۰۱)
db/schema.sql               ← جدول‌ها و توابع اختصاصی با پیشوند q56_
```

## ۳. راه‌اندازی Supabase (یک بار)

۱. **SQL Editor** پروژه را باز کن و محتوای [`db/schema.sql`](db/schema.sql) را اجرا کن.
   همهٔ جدول‌ها با `q56_` شروع می‌شوند، پس با `tafsirs`، `comments`، `site_meta`، `mizan_*` و
   `cinema_*` موجود شما هیچ تداخلی ندارند.

۲. **Authentication → Providers → Email** را روشن بگذار.
   برای اینکه دو نفر بدون تأیید ایمیل وارد شوند:
   **Authentication → Sign In / Providers → Email → Confirm email** را خاموش کن.
   (در حالت روشن، کاربر اول باید لینک ایمیل را باز کند.)

۳. **Authentication → URL Configuration**:
   - `Site URL`: آدرس نهایی سایت (مثلاً `https://username.github.io/vaqia/`)
   - `Redirect URLs`: همان آدرس + `http://localhost:3000/**` برای توسعه

۴. با **دو ایمیل** حساب بساز. اولین ورود هر حساب به‌صورت خودکار یکی از دو جایگاه
   (`slot = 1` یا `slot = 2`) را می‌گیرد. نفر سوم فقط می‌تواند بخواند و چیزی ثبت کند.

۵. کلید عمومی را در [`assets/js/config.js`](assets/js/config.js) بگذار. کلید `publishable`
   برای مرورگر امن است؛ **هیچ‌وقت** کلید `service_role` یا `secret` در این فایل نگذار.

> اگر SQL اجرا نشده باشد، سایت در «حالت محلی» با `localStorage` کار می‌کند تا خراب به نظر نرسد؛
> با اجرای SQL و رفرش، همه‌چیز به Supabase وصل می‌شود.

### چطور شمارنده کار می‌کند

- هر بار که به آخر سوره برسی، کارت «به آخر سوره رسیدی» ظاهر می‌شود؛ دکمهٔ **ثبت تلاوت کامل**
  یک ردیف در `q56_read_events` می‌سازد (تابع `q56_increment_read`).
- شمارنده‌های هدر از `q56_counter_summary()` می‌آیند: برای دو جایگاه، تعداد و آخرین زمان.
- با **دوبار زدن روی نام «واقعه»** در هدر (یا کلیک روی هر شمارنده) تاریخچه باز می‌شود:
  روز و ساعت شمسی به وقت تهران، گروه‌بندی‌شده بر اساس روز.
- خواندن شمارنده‌ها و تاریخچه برای همه آزاد است؛ نوشتن فقط با ورود.
  اگر می‌خواهی تاریخچه خصوصی شود، در `db/schema.sql` دسترسی `anon` را از
  `q56_read_history` بگیر: `revoke execute on function public.q56_read_history(integer) from anon;`

## ۴. تفسیر

سایت تفسیر را از `data/tafsir/` می‌خواند و خودش بلوک‌بندی و صفحه‌بندی می‌کند:

- فایل‌ها را با نام‌های `499.json`، `500.json`، `501.json` در `data/tafsir/` بگذار
  (همان فایل‌های خودت، بدون تغییر).
- ساختار مورد انتظار: `{ "content_id": 499, "text": "..." }` — همان چیزی که داری.
- `data/tafsir/manifest.json` اختیاری است؛ اگر فایل بیشتری اضافه کردی، نامشان را آنجا بنویس.
- صفحه‌بندی بر اساس حجم متن و مرز پاراگراف است (حدود ۱٬۹۰۰ نویسه در هر صفحه)؛
  عنوان‌ها تنها در انتهای صفحه نمی‌مانند.
- هر آیه در تفسیر، دکمهٔ «تفسیر این آیه» دارد که مستقیم به همان صفحه می‌رود.

تا وقتی فایل‌ها نباشند، تب تفسیر یک کارت راه‌اندازی نشان می‌دهد که می‌توانی فایل‌ها را
از همان‌جا موقتاً انتخاب کنی و پیش‌نمایش را ببینی (هیچ‌چیز آپلود نمی‌شود).

## ۵. انتشار روی GitHub Pages

```bash
git init
git add .
git commit -m "vaqia 56"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO.git
git push -u origin main
```

بعد در ریپو: **Settings → Pages → Source: Deploy from a branch → Branch: main / (root)**.
فایل `.nojekyll` هست، پس همهٔ فایل‌ها مستقیم سرو می‌شوند.

اگر در زیرمسیر منتشر می‌کنی (`/REPO/`)، همهٔ مسیرها نسبی هستند و لازم نیست چیزی عوض کنی —
فقط `Site URL` سوپابیس را هم همان زیرمسیر بگذار.

## ۶. استفاده

| کار | راه |
| --- | --- |
| سوره / تفسیر | سوییچ وسط هدر، یا کلید `S` و `T` |
| تاریخچه | دوبار زدن روی نام «واقعه» یا کلیک روی شمارنده |
| صفحهٔ بعد/قبل تفسیر | دکمه‌های پایین، یا `←` / `→` |
| پرش به آیه | دکمهٔ «پرش به آیه» یا `#surah/56` |
| بزرگ‌تر کردن متن | `A+` در نوار ابزار یا داک شناور |
| پوسته | دکمهٔ ماه/خورشید در هدر (در پروفایل هم ذخیره می‌شود) |
| نشان‌کردن آیه | قلب زیر هر آیه (در همین مرورگر می‌ماند) |

## ۷. نکته‌های فنی

- **فونت‌ها**: Vazirmatn برای رابط، Amiri Quran برای متن قرآن، Lalezar برای تیترها (Google Fonts).
- **تاریخ شمسی** با `Intl.DateTimeFormat('fa-IR')` و منطقهٔ `Asia/Tehran`؛ بدون کتابخانهٔ اضافه.
- **پوسته‌ها** با CSS variables روی `html[data-theme]`؛ انتخاب در `localStorage` و پروفایل.
- **بدون داده‌ی ساختگی**: اگر فایل تفسیر نباشد، هیچ متنی از خودش نمی‌سازد.
- **دسترس‌پذیری**: `dialog` بومی، `aria-live` برای شمارنده‌ها و توست‌ها، `prefers-reduced-motion`،
  کنتراست متن، و پشتیبانی از کیبورد.
